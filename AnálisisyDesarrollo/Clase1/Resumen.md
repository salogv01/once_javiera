# Resumen

El **análisis** y el **diseño** son etapas fundamentales en el desarrollo de software, ya que permiten comprender el problema y planificar la solución antes de comenzar a programar. El análisis se enfoca en identificar las necesidades de los usuarios, los requisitos del sistema y las restricciones existentes, mientras que el diseño define la estructura del sistema, sus componentes, las tecnologías que se utilizarán y la forma en que interactuarán. Una mala definición de los requerimientos es una de las principales causas del fracaso de los proyectos de software, y corregir errores resulta mucho más costoso cuanto más tarde se detecten.

## Ciclo de vida del software

El ciclo de vida del software está compuesto por varias fases que van desde la idea inicial hasta el mantenimiento del sistema:

1. **Análisis de requerimientos**
2. **Diseño**
3. **Implementación o programación**
4. **Pruebas**
5. **Despliegue**
6. **Mantenimiento**

Primero se realiza el análisis de requerimientos, luego el diseño, seguido por la implementación o programación. Después se llevan a cabo pruebas para detectar y corregir errores, se realiza el despliegue para que los usuarios puedan utilizar el sistema y, finalmente, se entra en la etapa de mantenimiento, donde se solucionan problemas y se agregan mejoras. Aunque estas fases suelen presentarse de forma ordenada, en la práctica pueden repetirse varias veces a medida que surgen nuevas necesidades.

## Metodologías estructuradas

Las metodologías estructuradas se caracterizan por una planificación detallada antes de iniciar el desarrollo.

### Modelo Cascada
Organiza las fases de manera secuencial, avanzando de una etapa a otra sin regresar.

### Modelo en V
Amplía la idea del modelo Cascada al asociar cada fase de desarrollo con una fase de pruebas correspondiente.

### Modelo Espiral
Combina el desarrollo por etapas con el análisis de riesgos, permitiendo mejorar progresivamente el producto mediante ciclos repetitivos.

Estas metodologías son especialmente adecuadas para proyectos con requisitos claros, sistemas críticos y entornos donde se requiere una gran precisión en la planificación y el control del proceso.
